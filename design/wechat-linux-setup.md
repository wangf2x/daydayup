# 微信账号和 Linux 接入操作手册
> 历史部署参考：当前选定的是 CloudBase 家庭轻体验版，详见 [CloudBase 方案](cloudbase-experience-design.md)。本手册的 Linux 主机、域名、Compose、Nginx 和 SSH 操作不是当前部署步骤；不要照此在服务器创建第二版服务。
本手册对应家长多孩子、江苏小学初中全学科、仅识别题号标记题的第二版方案。账号和域名步骤现在可以办理；第二版应用、检测模型和部署文件仍需按 [详细设计](design-v2.md)实现后才能部署。当前仓库中的应用是旧原型，不能作为新规则已经生效的证明。
服务器已通过只读检查：Ubuntu 22.04.5、Docker 和 Compose 可用，宿主机 Node.js 为 22，当前使用内网 SSH。建议保留系统环境，在容器内运行 Node.js 24。

## 二 查找小程序 AppID
1. 在电脑浏览器打开 [微信公众平台](https://mp.weixin.qq.com/)，由你使用已注册小程序对应的管理员账号登录，并自行完成扫码验证。
2. 确认进入的是“小程序”后台，而不是公众号后台或个人微信设置。公众号 AppID 不能直接替代本项目的小程序 AppID。
3. 在后台找到“开发与服务 → 开发管理 → 开发设置”。旧版界面可能显示“开发 → 开发管理”或“开发设置”，以“开发者 ID”区域为定位目标。
4. 找到 `AppID（小程序ID）`，复制完整值。AppID 常以 `wx` 开头。
5. 核对本次要使用的小程序名称与主体，避免复制同账号下另一应用的 AppID。
6. 实现/联调时，将 AppID 填入项目根目录 `project.config.json` 的 `appid`。新后端的 `WECHAT_APP_ID` 必须与它一致。
微信工具与小程序 AppID 是小程序开发的基础准备项。[腾讯官方准备说明](https://docs.cloudbase.net/quick-start/frameworks/wechat-miniprogram)
如果暂时看不到菜单，先确认当前登录角色是否为管理员或具有开发设置权限；可以提供菜单名称或脱敏截图协助定位，不必分享登录凭据。
## 三 获取 AppSecret 并配置成员
### AppSecret
在同一“开发者 ID”区域查看开发者密码/AppSecret 相关操作。根据当前账号情况，由管理员按后台要求查看、生成或管理密钥，并在服务器配置中填写 `WECHAT_APP_SECRET`。
已有小程序若已连接其他业务，不要为了测试随意重置密钥；重置可能影响旧系统。若无法读取原密钥，先确认已有集成，再安排密钥轮换。本项目不需要将 AppSecret 写入小程序、提交版本库或传给手机。
### 开发人员
在微信公众平台找到“管理 → 成员管理”或同义菜单，添加实际操作微信开发者工具的人，授予开发和必要的开发设置权限。开发人员使用自己的微信登录工具，不借用管理员个人微信。
### 体验人员
将需要演示的家长微信加入“体验成员”。代码上传后，在“版本管理 → 开发版本”中将对应构建设为体验版，再由这些成员扫码进入。开发工具预览和体验版是不同入口，体验权限以后台当前状态为准。
仅有二维码不表示任何人都能访问未发布版本。公开发布需另行完成平台要求的资料、类目、备案与审核流程，具体办理状态以你的小程序后台为准。
## 四 确定公网入口和域名
已验证的 `10.1.68.75` 是内网地址。SSH 能从当前电脑连接，并不能证明家长手机使用蜂窝网络时可以访问这台服务器。
先选择一种实际可控的路径：
| 路径 | 需要确认的条件 | 域名指向 |
| --- | --- | --- |
| 现有公网网关 | 网关能通过内网/VPN访问本服务器，并允许增加站点 | 网关的公网入口 |
| 路由器或网络出口映射 | 有可用公网入站地址和配置权限，80/443 可达 | 实际做入站转发的地址 |
| 固定域名受控隧道 | 服务稳定、有自有域名、支持 HTTPS、权限和费用可接受 | 隧道提供的 CNAME 或入口 |
| 同网开发调试 | 手机确实能访问服务器所在网络 | 用于开发验证，不作为异地稳定演示的交付条件 |
不要把检测到的公网出口地址直接当作域名目标；先验证它是否能入站映射到本机。也不能通过盘点本机自动证明你拥有哪些域名。
域名建议使用单一子域，例如 `learn-api.example.com`，统一承担业务请求、上传和认证图片下载。确认 DNS 控制权限后，按选定入口设置 A/AAAA 或 CNAME；只有实际提供 IPv6 入站时才添加 AAAA。
证书必须匹配域名且链完整。若证书终止于公网网关，则由网关续期和转发；若入口直接部署在本服务器，则由项目入口代理提供证书。使用 ACME 自动签发时，还需满足所选 HTTP 或 DNS 验证方式的网络和域名条件，不能在没有入口和域名权限时直接假设签发成功。
HTTPS、有效证书和平台域名校验要求见 [腾讯域名配置说明](https://docs.cloudbase.net/lowcode/practices/miniapp-guide/downloadfile-guide)。域名与小程序的备案、主体及类目事项应按实际地域和微信后台要求核验，不能因服务器能连外网就视为已满足。
## 五 配置微信服务器域名
公网 HTTPS 入口能正常访问后，在小程序后台“开发设置 → 服务器域名”添加：
| 类别 | 本项目使用方式 | 示例 |
| --- | --- | --- |
| request 合法域名 | 登录、任务、题目、挑战和图片访问授权 | `https://learn-api.example.com` |
| uploadFile 合法域名 | 上传照片和挑战作答区域 | `https://learn-api.example.com` |
| downloadFile 合法域名 | 下载受认证保护的原图和题目裁图 | `https://learn-api.example.com` |
填写域名，不把 `/api/v2` 路径写进域名白名单。服务器域名配置和网页 `web-view` 业务域名不是同一项；本项目不因使用 API 就必须配置 `web-view`。
模型服务地址和 `api.weixin.qq.com` 由后端访问，不让手机直接携带服务端密钥调用。若未来改用独立对象存储下载域名，还需配置该下载域名，并检查签名 URL 是否重定向到其他域名。
完成后刷新开发者工具配置，关闭“不校验合法域名”的临时开发开关，再验证请求、上传和下载三个环节。只在开发工具放宽校验不能代替正式域名配置。
## 六 配置照片处理隐私说明
在小程序后台的用户隐私保护指引配置中，填写实际收集和处理照片的用途、保存方式、提供服务的第三方和删除入口。菜单可能位于“设置 → 服务内容声明”或隐私保护相关区域，以后台当前界面为准。
说明内容至少与实际设计一致：家长为孩子上传学习照片；原图在服务器私有存储；只对确认标记题裁图进行 AI 识别和练习处理；私人照归家长独立相册，不绑定孩子，只存储不调用识别；可删除照片和孩子档案，删除孩子不删除家长私人相册。
微信隐私授权与上传用途确认是两个环节。用户不同意拍照/相册相关授权时，不能强制继续调用受限制接口，也不能把 AppSecret 当作授权凭证。
## 七 确认 AI API 能力
### DeepSeek
1. 打开 [DeepSeek API 平台](https://platform.deepseek.com/)，确认登录的是可管理 API 的账户。
2. 在 API Keys 等相应页面创建本项目专用密钥，查看可用额度或账单设置。
3. 查看当前账户允许调用的模型，并确认图片输入能力。官方文档现有 `deepseek-flash` 视觉输入说明；实施时仍以账户和当前可用模型为准。[视觉接口](https://api-docs.deepseek.com/guides/vision/)、[模型查询接口](https://api-docs.deepseek.com/api/list-models/)
4. 密钥在服务器配置中填写，先测试一张人工裁出的标记题，确认图片请求、文本/公式、识别结构和额度；原卷不测试对错判定。
5. 记录服务商、模型 ID、协议及计费方式，不把网页聊天成功当作 API 测试成功。
### 豆包和火山方舟
1. 进入 [火山方舟控制台](https://console.volcengine.com/ark)，确认账户已经开通相应 API 服务。
2. 根据控制台流程创建本项目 API Key，开通具有图片理解能力的模型或对应推理接入点。
3. 记录控制台实际提供的模型 ID/接入点 ID、地域和 API 地址。豆包 App 登录状态不能直接替代方舟密钥。
4. 按官方图片理解样例验证一个已标记题裁图，再验证识别结构化输出与独立挑战批改；不同协议要分别适配，不直接复用旧百炼参数。[图片理解文档](https://docs.volcengine.com/docs/ark/image-understanding?lang=zh)
### coplit
请先确认完整产品名称。若指 GitHub Copilot，它存在官方服务端 SDK 接入方式，但需要单独确定认证、可用模型、配额与计费；若指 Microsoft Copilot，则按该产品实际 API 能力另外评估。
本方案先保留适配接口，优先用已开通且验收通过的独立模型 API 跑通业务，不要求同时购买三个服务。不得通过抓取聊天网页会话代替可靠的后端接入。[GitHub 官方服务端接入](https://docs.github.com/en/copilot/how-tos/copilot-sdk/setup/backend-services)
## 八 Linux 部署实施步骤
以下为第二版的实施顺序和部署交付约定。本轮只执行了只读盘点，下面涉及目录、容器、网络和证书的操作尚未执行。当前旧仓库没有第二版 `compose.yaml`、数据库迁移命令或检测模型，不能直接运行尚未交付的部署命令。
### 连接和目录
Windows PowerShell 连接已经验证可用：
```powershell

```
后续确定实施时，将第二版放到独立目录，例如 `/home/wangfei/daydayup-v2`；原 Windows 项目及备份继续保留。建议发布包目录结构：
```text
daydayup-v2/
  compose.yaml
  .env.example
  .env                     本机填写，不进入代码包
  images-or-build-context/ 已测试的 API 和 Worker 镜像或构建上下文
  config/nginx.conf        与公网入口一致的代理配置
  models/                  已验证许可和效果的本地检测模型
  migrations/              版本化数据库迁移
  scripts/                 健康检查和备份恢复工具
  data/                    私有图片持久数据
  backups/                 本机临时备份并同步至选定的异地位置
```
传文件时 `scp` 指定端口用大写 `-P`，与 `ssh -p` 不同。先在目标创建新的发布目录，再上传经过校验的第二版发布包；不对现有其他业务目录执行覆盖同步。
### 容器和配置
Compose 需要交付 `api`、`worker`、`detector`、`postgres` 和入口代理服务。宿主机保持 Node.js 22，应用镜像使用受维护的 Node.js 24 系列并锁定发布版本/摘要；数据库版本与迁移一同锁定，不用无约束 `latest`。
数据库和检测服务不发布公网端口。API 默认仅在容器内部 3000 监听；公网入口转发到它。需要本机临时健康检查时，可将 API 发布为 `127.0.0.1:3000:3000`，不能把数据库映射为公网服务。
第二版 `.env` 的建议配置结构如下；这些字段是新实现的配置合同，并非全部已经被旧代码读取：
```dotenv
NODE_ENV=production
HOST=0.0.0.0
PORT=3000
PUBLIC_API_ORIGIN=https://learn-api.example.com
WECHAT_APP_ID=填写实际小程序AppID
WECHAT_APP_SECRET=仅在服务器填写
DATABASE_URL=仅在服务器填写数据库连接
STORAGE_BACKEND=local
STORAGE_ROOT=/var/lib/daydayup/assets
VISION_PROVIDER=填写已验证的服务商
VISION_MODEL=填写支持图片输入的模型ID
TEXT_PROVIDER=填写已验证的服务商
TEXT_MODEL=填写解析生成和挑战批改模型ID
MODEL_API_KEY=仅在服务器填写
MARK_RULE_VERSION=mark-v2
```
多个服务商使用各自密钥命名空间；以上单个 `MODEL_API_KEY` 仅展示最小配置概念。生产验证应拒绝空密钥、缺少检测模型、无效教材配置或开发访客模式。“只识别标记题”是业务硬约束，不提供一个可随意关闭它的环境开关。
创建实际 `.env` 后仅授予部署用户必要读权限，例如 `chmod 600 .env`。配置校验输出不能打印密钥。无需把 `.env` 内容回传到聊天或提交 Git。
### 代理配置参考
下例适用于 Nginx 容器与 `api` 位于同一 Compose 网络、且本机负责终止 HTTPS 的情况；域名、证书路径与实际入口不一致时必须调整。公网网关终止 HTTPS 时，在网关配置同等转发和限额，不重复套用错误的证书位置。
```nginx
server {
    listen 443 ssl;
    server_name learn-api.example.com;
    ssl_certificate     /etc/daydayup/tls/fullchain.pem;
    ssl_certificate_key /etc/daydayup/tls/privkey.pem;
    ssl_protocols TLSv1.2 TLSv1.3;
    client_max_body_size 10m;
    location /api/ {
        proxy_pass http://api:3000;
        proxy_http_version 1.1;
        proxy_set_header Host $host;
        proxy_set_header X-Forwarded-Proto $scheme;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_read_timeout 60s;
    }
}
```
上传上限以应用配置为准，代理限额略大于单张 8MB 图片以容纳 multipart 开销。新设计长任务返回任务 ID，不能靠把代理超时无限加大来解决模型处理延迟。代理指令语义见 [Nginx 官方文档](https://nginx.org/en/docs/http/ngx_http_proxy_module.html)。
### 启动顺序
第二版发布包需提供并验证下面的执行合同；实现完成前，先不要在旧项目目录尝试这些命令：
```bash
# 仅在已交付 v2 发布包的目录中执行。
test -f compose.yaml
docker compose --project-name daydayup-v2 config --quiet
docker compose --project-name daydayup-v2 up -d postgres
docker compose --project-name daydayup-v2 run --rm api npm run db:migrate
docker compose --project-name daydayup-v2 up -d api worker detector gateway
docker compose --project-name daydayup-v2 ps
```
迁移执行一次并检查退出码，失败时不要继续启动处理真实数据的 Worker。镜像应包含编译产物和已锁定依赖，不能以本次旧项目无需安装第三方依赖推断新版本也无需构建。
启动后内部健康检查需要验证 API、数据库、图片目录和任务 Worker；外部健康检查不返回密钥和内部连接串。第二版建议提供 `GET /api/v2/health` 与受控的依赖就绪检查；旧版目前只有 `/api/health`，两者不可混称。
### 备份和回滚
数据库采用一致性备份，图片存储同时保存对应索引与版本。备份同步到已确认的另一个位置，不能只把同一磁盘上的目录当成灾难恢复手段。
发布前记录当前版本、镜像摘要、迁移版本和备份位置。回滚先检查迁移是否向后兼容；不能把旧应用随意连接到已执行不兼容迁移的新库。首次交付必须演练恢复到独立目录/数据库，不在唯一生产数据上测试恢复。
## 九 手机微信操作步骤
1. 开发电脑安装 [微信开发者工具](https://developers.weixin.qq.com/miniprogram/dev/devtools/download.html)，使用有开发权限的微信扫码登录。
2. 导入实际第二版小程序项目根目录，检查 AppID 与服务器配置一致。
3. 配置第二版 API 地址为 `https://learn-api.example.com/api/v2`。当前旧版 `miniprogram/config.js` 的 `127.0.0.1` 只指本机，不能直接拿来访问 Linux 服务器。
4. 编译后，在开启合法域名校验的条件下，验证登录、上传和下载；这一步须等待第二版代码实际交付。
5. 点击“预览”，使用具备相应权限的手机微信扫码。出现权限、隐私或登录失败时保留错误码和 requestId，不把密钥作为排查材料发送。
6. 首次进入，创建两个不同年级的孩子，配置实际教材和学科，并选择一个孩子开始拍照。
7. 拍摄含 √、五角星和三角形叠加题号的试卷，确认标记与题目边界后等待后台识别。
8. 检查未标记题没有识别文字、答案或题库记录；再试一张全无标记试卷，验证不产生云端 OCR 调用。
9. 验证标记题直接归档且默认未掌握，原卷没有判题；测试单科默认 6 题、大综合默认 15 题及自定义数量、9:1 和自定义掌握比例，提交后自动批改。
10. 验证挑战答错题自动归未掌握并进入“挑战赛”，已掌握题答错自动移回，答对不自动掌握；大题计 1 题且小问错误触发整题迁移；误判纠正仅在无后续操作/其他有效错误时恢复原状态。检查两种模式错误的筛选及 Word 导出。切换另一个孩子，确认学习数据不串用；私人照仍在同一家长独立相册，无识别任务和模型调用；切换家长账号不可访问另一家长私人照。
    同时验证部分正确与主动不会迁移、缺额确认后补足，以及五菜单中的举一反三生成入库。测试周更新可调周期、重复运行幂等、费用上限与增量保留历史；实际生产调度只在部署配置完成后启用。
11. 上传构建至开发版本，管理员设为体验版，加入实际演示家长后扫码测试。
12. 至少增加一次手机蜂窝网络测试，证明演示不依赖电脑所在 Wi-Fi；Android 和 iPhone 按实际可用设备分别记录。
未完成第二版实现之前，旧原型可以作为页面参考或独立演示，但其整页识别和旧标记语义不能用于以上验收。
## 十 常见问题定位
| 现象 | 优先检查 |
| --- | --- |
| 找不到 AppID | 是否进入小程序后台、当前成员权限、开发设置菜单 |
| 能 SSH 但手机不能访问 | 内网路由、实际公网入口、80/443 映射、DNS、证书 |
| 服务器访问自己成功，蜂窝网络失败 | 出站能力和入站能力混淆；外部防火墙或转发路径未打通 |
| 登录失败 | 前后端 AppID 是否一致、密钥状态、微信返回码、code 是否重复使用 |
| 上传成功但图片不显示 | downloadFile 合法域名、认证头、授权 URL、证书与重定向 |
| 模型返回 401/403 | API 权限或密钥问题，不等同于聊天账号登录成功 |
| 模型返回 429 | 调用配额或费用限制，查看队列退避与额度 |
| 未标记题被识别 | 先检查候选范围和裁图链；这是业务缺陷，不能以模型行为解释为正常 |
| 长时间排队 | Worker、持久任务、供应商配额、检测耗时及重试状态 |
| 旧版直接在主机运行失败 | 当前主机 Node.js 22，而原型要求 24；采用隔离容器，不盲目覆盖主机版本 |
