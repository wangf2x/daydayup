复查日期：2026-10-23。依据为本项目 `design/` 中的详细设计、验收清单、操作手册及本轮用户说明。此次为文档一致性与实现可行性检查，没有运行第二版应用、重新登录服务器或验证模型准确率，也未重新核验平台政策和外部链接。当前修订 v2.10。
## 结论与已确认规则
当前设计按用户答复更新为 v2.10。原先 Q01—Q03 已关闭，另已确认 Q04：挑战保留自动批改。以下是当前权威规则，原“先判错再归档”“掌握仅覆盖判错题”“固定六题”“只从未掌握抽题”“挑战错题仅提示移回”等均被替代。
| 项目 | 用户确认结果 |
| --- | --- |
| Q01 掌握范围 | √、☆、△ 筛选需要整理的题目，与原卷作答无关；全部新归档题默认未掌握 |
| Q02 大题范围 | 大题序号有标记时处理整个大题及全部小问 |
| Q03 原卷归档 | 不需要判题，直接识别标记题；科目确定且内容完整即归档，无对错复核 |
| Q04 挑战判题 | 挑战提交保留自动批改，答案/成绩保存到本场作答记录 |
| 挑战模式与题量 | 单科默认 6、大综合默认 15，数量均可调整；从现有题库抽题 |
| 掌握比例 | 默认未掌握 9 份、已掌握 1 份，可自由配置，总计 10 份 |
| 错误归档 | 挑战答错归未掌握，已掌握也移回；统一记入“挑战赛”，不复制原题 |
| 目录命名与位置 | 每科下整理、举一反三、挑战赛、已掌握、所有题型并列；前四者互斥，所有题型汇总 |
| 题库生成与更新 | 按题型生成相似题，校验后发布至举一反三，默认每周更新且可调周期 |
| 特殊结果与缺额 | 部分正确/主动不会均迁挑战赛；缺额提示后须明确确认才可跨掌握池补足 |
| 页面标签筛选 | 整理/已掌握/所有题型新增 √、☆、△ 按钮；全灰默认包含全部，点击变白排除对应项，再点恢复 |
| 大题计数与迁移 | 整道大题计 1 题；任一小问答错、部分正确或明确不会，整题迁入挑战赛 |
| 误判恢复 | 无后续操作或其他有效错误时，恢复本次自动迁移前目录及掌握状态 |
| 私人照归属 | 家长独立相册，不绑定孩子，不随孩子切换或删除 |
设计默认值仍包括：按整数份调整比例、半题取整优先未掌握、题数上限初设50可配；needs_review 不迁移；较新的人工状态受版本保护。部分正确和主动不会迁移已成为用户确认规则，不再列作未定建议。
## 本轮同步修订
三类标签筛选按用户最新修正为“命中任一仍为灰色的标签即显示”，替代之前任一排除命中即隐藏的设计；√ 白、☆ 灰时 √+☆ 题继续显示，仅当该题全部标签被取消才隐藏。无标签题保留；页面重新进入或切换范围重置全灰、详情返回保留，这些仍为设计默认值。分页、总数、批量勾选和 Word 导出使用一致条件；不改变原卷识别范围、题目掌握状态或挑战抽题规则。同步 R30、E13—E19，功能尚未实现。
- 原卷链路移除判题、评分、原作答提取及原卷错误率；只保留内容识别异常修正。
- 题目内容、二态掌握、参考解析、挑战作答与错误事件分别保存；归档与默认未掌握事务一致。
- 抽题保存目标配额及用户确认的实际补足配额；本次确认不改变长期设置，变化需重新确认；不重复、不临时生成。
- 相似题经校验发布到举一反三后进入抽题池；周更新按库存与预算增量补充，不重置旧题掌握或历史。

- 保留前轮已补齐的私人照转换、Linux 检测边界和重复导入规则。

### 本轮可直接补齐的技术设计
1. 补上 challenge 与 attempt 分离：抽题场次就绪不等于某次作答完成，重做保留新 attempt 与历史成绩；新增创建作答接口。
2. 明确 organized → challenge 即使同为 unmastered 也必须迁移、递增版本并写事件，防止只更新掌握状态导致目录未移动。
3. 补齐导出菜单、内容版本、掌握版本及 collection 快照字段，确保五菜单导出与页面一致。
4. Q10 已确认手写拍照为可选作答方式，答案图片对应当前题和尝试、不需三符号；原卷拍照仍依三符号筛选。
5. 修正汇总接口中的旧“已复核”门槛：已完成识别的原卷题即可归档统计，不重新引入对错复核。
以上已更新详细设计和验收清单，未实现应用代码。后续仍需将接口表落实为请求/响应结构、错误码、数据库约束及测试，不把表格视为可运行 API。

## v2.10 全流程复查结论与开发缺口
业务主线已经可以用于页面原型与基础模块开发，但还不能视为完整冻结的开发规格。原卷导入、五菜单、三标签筛选、掌握迁移和两类挑战的主要边界已明确；剩余不确定集中在评分口径、复核操作、生成题可用性和运行验收。此次依据本地设计及验收文档检查，没有验证检测器、模型质量、接口运行、微信平台要求或服务器当前状态。
### 已在本轮补齐的设计
1. **用户新增确认**：Q08/Q09/Q11 均关闭；补齐整题计数、误判恢复的条件补偿，以及家长私人相册的权限/接口/转换/删除边界。
2. **页面筛选与挑战抽题分开**：修正“列表与抽题必须同查询”的过宽描述。列表、数量与导出同条件；挑战用独立配置与可练资格，不继承 √/☆/△ 按钮选择。
3. **标签证据与题目标签分开**：新增 question_labels，原照片标记留在 question_marks；生成题无须伪造照片区域。挑战选择“不会”保留作答结果，不自动打 ☆，避免改变页面筛选。
4. **已归档与可练分开**：新增可练资格及版本依赖。缺少干净题干、参考答案或评分细则的题可在题库查看，但不虚增可立即开赛库存。
5. **模型输入按任务区分**：原文 ai_runs 只允许裁图会误伤生成与手写挑战批改，现明确导入裁图、生成题目版本、挑战答案各自授权范围，私人照始终零模型处理。
以上是文档与逻辑合同补齐，未编写或运行第二版业务实现。

| D11 / 高 | 参考答案可见性与练习复用存在容易误实现的边界 | 区分已发布题库解析与本场尚未公开的评分数据；提交前不得泄露本场私有答案，但不承诺复习题答案从未展示。题目详情/导出/缓存/结果接口需有一致权限矩阵，不因某场未交卷就全局锁死全部历史解析 |
| D12 / 高 | 部分失败与复核结果读取合同仍需字段级细化 | 已修正结果接口允许 review_required 查看待处理项与已有结果，并区分小问错误证据与整题结果；仍需补“部分小问判定、其余调用失败”的 schema、重试范围及幂等键，以及暂定/最终统计字段，避免复核死路或重复记错 |
| D13 / 中 | 定时生成的费用、幂等与库存竞争 | 手动与定时任务共用预算预留和库存锁；按实际可用量复验、调用后记账、失败释放预留；重启只补执行一次，周期变更/模型停用/预算耗尽有记录。增量发布，禁止无限递归生成变式 |
| D14 / 中 | Word 与可练展示共享清理成果尚无实体定义 | 统一保存干净题干、图表及清理版本；避免每次挑战/导出重新猜测手写去除。人工修订可恢复资格，失败须显示具体原因；公式/图表和长阅读材料要在实际 Word/WPS 与手机验证 |
| D15 / 中 | 工程交付门槛尚未量化 | 提交数据库 DDL/约束/迁移、OpenAPI 请求响应与错误码、配置样例、模型适配器与回放样例、任务/存储恢复演练和真机记录；先测真实基线，再约定检测/OCR/批改/生成准确性与延迟、费用门槛，不虚构已达标百分比 |
D01（严格范围检测）、D03（跨页材料）、D04（孩子归属纠错）、D07（保留与费用）和 D08（独立验证集）仍有效。全学科是已确认的范围；可以分批验证，但不能用数学跑通替代全部实际课程验收。原型能归档不等于题库能自动正确出题/批改，两个门槛必须分别验收。

## CloudBase 家庭轻体验版复核（2026-10-24）

本轮确认将 CloudBase 作为家庭内部体验的目标平台，新增技术基线见 [CloudBase 方案 v3.0](cloudbase-experience-design.md)。现有业务规则（多孩子隔离、五菜单、挑战与掌握迁移）继续沿用；技术方案不再按 Linux Compose 单机实施。

新增确认：不要求家长手动框选；多页可作为一次导入批次；高置信度检测、完整题干及明确科目时直接入库，低置信度不调用 OCR 并提示重拍；该页识别结果全部处理后原图保留六个月，未完成照片最多三十天；到期只删原图，结构化题库和必要图表附件保留；目标年度付费不超过 100 元，达到预算后暂停付费调用；首轮接入腾讯试题 OCR 和混元，保留供应商适配接口。

“一题一次 OCR”是业务题块口径，不是供应商账单单位。若一页有多道标记题，必须先检测并裁切；同一道题的多个符号只算一道题。真实调用按接口支持的批量能力提交，并分别记录题块数、请求数、图像数、Token 和账单用量。

编码前仍须现场核验：CloudBase 免费环境/续期资格；云函数、定时任务、容器或检测模型的资源限制；所选数据库的事务能力；试题 OCR 和混元账户的准确配额、计费单位及区域；年度预算告警能力。标记检测及跨页关联必须用脱敏实拍样例验证，置信度门槛不预设。原小程序服务密钥和上传私钥已在设计材料中暴露，应视为失效风险并在控制台轮换；不得复制到新设计、代码或聊天中。
